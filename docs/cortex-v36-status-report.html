Resumen Ejecutivo

Cortex v2.3 era un sistema de aprendizaje continuo funcional pero con 6 vulnerabilidades de seguridad, 0 tests y un observer que lanzaba 11 procesos shell por cada tool use. Sinapsis v4.3, el fork de Luis, aportaba ideas valiosas (Dream Cycle, tests, installer) pero consumia 10,475 tokens/sesion — 4x mas que Cortex.

La mision del roadmap v3.0 fue clara: importar lo mejor de Sinapsis, arreglar la seguridad de Cortex, y crear lo que ninguno tenia. El resultado es Cortex v3.6.

Que se Importo de Sinapsis

5 conceptos clave de Sinapsis v4.3 fueron importados, adaptados y mejorados para encajar en la arquitectura Cortex.

⚛
Sinapsis

Dream Cycle

5 modulos de higiene del conocimiento: Jaccard dedup, deteccion de contradicciones, staleness scoring, validacion regex y health score.

+ Fix Unicode tokenizer + Fix false positives ("document"/"domain")
⚡
Sinapsis

Inyeccion en Tiempo Real

Domain pre-filter por stack del proyecto, tracking de activaciones, max 3 instincts por inyeccion.

+ Domain filter (React, Node, Python, Rust, Go, Supabase)
☑
Sinapsis

Tests

40 tests portados de Sinapsis como base. 84 tests nuevos escritos para Cortex. Total: 124 tests en 8 suites.

CI: GitHub Actions, macOS + Linux, Python 3.9/3.12, Node 18/22
📦
Sinapsis

Installer Inteligente

Deteccion de version instalada, upgrade path visual, preservacion de datos de usuario durante actualizaciones.

+ PowerShell cross-platform + path traversal protection
👥
Sinapsis

UX Participativa

El usuario decide que se aprende. /cx-analyze genera propuestas, /cx-validate permite aceptar/rechazar con shorthand (A/X/S), /cx-promote permite promocion cross-project controlada.

Shorthand system: A=Accept, X=Reject, S=Skip, M=Merge, O=Omit, I=Install

Que se Mantuvo de Cortex

6 pilares arquitectonicos de Cortex original que resultaron superiores a sus equivalentes en Sinapsis.

👁
Cortex

Observation Pipeline

Captura asincrona de JSONL con 0 tokens inyectados. El observer nunca interfiere con la sesion del usuario.

Async mode, 10s timeout, zero token cost
🎯
Cortex

Sistema de Confianza

Escala continua 0.0-1.0 con decay proporcional a staleness. Draft (0-0.29), Hypothesis (0.30-0.49), Pattern (0.50-0.69), Instinct (0.70-0.89), Law (0.90+).

Sinapsis usaba tiers discretos (low/medium/high)
⚖
Cortex

Destilacion de Leyes

Promocion automatica de instincts a laws al alcanzar confianza 0.90+. One-liners inyectados en cada SessionStart.

Max 10 laws activas, cap at 0.95, auto-archive
🤖
Cortex

Sub-Agentes

3 agentes especializados: cortex-observer (Opus 1M), cortex-reviewer (Sonnet x3 paralelo), cortex-planner (Sonnet).

Sinapsis no tenia agentes delegados
🌄
Cortex

EOD/Resume

Resumen end-of-day con inyeccion automatica en la siguiente sesion. Mecanismo read-once via marker .eod-last-read.

Context bridge con TTL de 14 dias
💾
Cortex

Backup/Restore

Archivo .tar.gz portable con toda la base de conocimiento. Validacion de path traversal en la extraccion.

Preserva laws, instincts, memory, reflexes, proposals

Que es Nuevo

7 innovaciones que no existian ni en Cortex v2.3 ni en Sinapsis v4.3.

🐍
Nuevo

observe.py

Consolidacion del observer: de 11 spawns shell a 1 proceso Python.

~70ms vs ~800ms anterior
🔌
Nuevo

Skill Router

/cx-router: catalogo lightweight de comandos con coste de tokens y accion sugerida.

~50 tokens vs 4,400 de Sinapsis
💰
Nuevo

Token Budget Cap

Limite de 8,000 tokens/sesion. Instincts se omiten al exceder. Reflexes siempre pasan (safety exempt).

Archivo .session-token-budget
📈
Nuevo

Draft Auto-Promote

Instincts draft (conf < 0.30) se auto-promocionan a 0.35 tras 5+ activaciones en 3+ sesiones.

instinct-tracking.json
🏷
Nuevo

CORTEX-MANAGED

Marcadores en todos los hooks para deteccion fiable durante upgrades del installer.

Patron: # CORTEX-MANAGED
📄
Nuevo

yaml-utils.js

Parser YAML compartido con parseFloat correcto para confidence values. Elimina duplicacion entre injector y learner.

parseYamlFrontmatter + updateYamlField + listYamlFiles
🖥
Nuevo

Installer Cross-Platform (PowerShell)

Windows nativo via install.ps1. Misma logica de upgrade, preservacion de datos y deteccion de version que el bash installer.

powershell -ExecutionPolicy Bypass -File install.ps1

Roadmap Futuro

Fase 10 — Opcional / Diferido

Items considerados durante el roadmap v3.0 pero diferidos por no ser prioritarios o por requerir cambios de infraestructura significativos.

SQLite + FTS5
Complejidad: Alta
Reemplazar JSONL por SQLite con busqueda full-text (FTS5) para queries complejas sobre observaciones. Requiere migrar el formato de datos y actualizar observe.py y session-learner.js.
Token Budget UI Cap
Complejidad: Media
Interfaz de configuracion para que el usuario ajuste el limite de tokens por sesion desde un comando interactivo, sin editar archivos manualmente.
Multi-Machine Sync
Complejidad: Alta
Sincronizacion de base de conocimiento entre multiples maquinas. Requiere definir estrategia de merge para instincts y laws conflictivos.
session-start.sh → Python
Complejidad: Media
Reescribir session-start.sh en Python para consistencia con observe.py y eliminar dependencias de BSD vs GNU date.
