Que hace cada uno (en palabras simples)

Cortex

Un diario inteligente que aprende de ti

Imagina que cada vez que usas Claude Code, alguien toma notas de todo lo que haces: que herramientas usas, que errores cometes, como los arreglas. Cortex hace eso automaticamente. Despues, detecta patrones ("siempre que editas un archivo, primero lo lees") y los convierte en reglas que Claude aplica solo en el futuro.

Sinapsis

Un sistema operativo para Claude Code

Sinapsis es un paquete que instalas con un solo comando. Te configura todo: skills que se cargan solo cuando las necesitas (ahorrando tokens), un onboarding guiado de 8 pasos, y un sistema de "suenos" que limpia automaticamente el conocimiento acumulado para que no se pudra. Bugs y Problemas Detectados

Bugs en Cortex
CRITICO
5 instincts de proyecto nunca se activan
Usan trigger_pattern en lugar de trigger. El injector.sh busca solo trigger, asi que estos instincts son invisibles. Afectados: gotcha-n8n-uid, gotcha-supabase-env, gotcha-kuma-sqlite, pattern-backup-manifest, pattern-pin-docker.
CRITICO
Session ID matching siempre falla
session-learner.js no puede filtrar observaciones por sesion. El log repite "Session X not found, falling back to last 200 lines". Analiza observaciones de TODAS las sesiones mezcladas.
MEDIO
Regex rota en gotcha-postgrest-no-fk-join.yaml
El trigger PGRST200|supabase|join|select.*,.*\(|embed causa "Unterminated group" en Node.js. Error silencioso en cada sesion.
MEDIO
stats.total_observations siempre en 0
El campo en memory.json no se actualiza nunca. Los datos reales estan en los JSONL pero la metadata de resumen esta desincronizada.
BAJO
git remote get-url en cada PreToolUse
Sin cache. En sesiones intensivas, acumula decenas de llamadas git/min. Impacto de rendimiento acumulativo.
Bugs en Sinapsis
MEDIO
_library/ vacio
La arquitectura describe un catalogo de 50+ skills on-demand, pero el directorio _library/ esta vacio en el repo. La promesa del skill router queda parcialmente incumplida.
MEDIO
Version desincronizada en install.bat
install.bat dice "Sinapsis v4.1" cuando install.sh ya muestra v4.3.0. _catalog.json tambien dice version "4.1".
BAJO
JS inline en scripts bash (400+ lineas)
Bloques node -e '...' de cientos de lineas incrustados en bash. Sin syntax highlighting, sin linting, dificil de debuggear.
BAJO
.gitignore incompleto
Solo excluye __pycache__/. No excluye .env, _operator-state.json, observations.jsonl ni _daily-summaries/.

Roadmap: Extender Cortex con lo mejor de Sinapsis

El objetivo no es reemplazar Cortex por Sinapsis, sino absorber las piezas que faltan manteniendo el cerebro entrenado intacto.
1
Fase 1 — Corregir bugs criticos de Cortex
  • Fix trigger_pattern → trigger en los 5 instincts de proyecto rotos. Son buscar-y-reemplazar, cero riesgo.
  • Fix session ID matching en session-learner.js para que filtre observaciones de la sesion actual, no las ultimas 200 globales.
  • Fix regex rota en gotcha-postgrest-no-fk-join.yaml: escapar el parentesis para Node.js.
  • Cache de git remote en injector.sh: guardar en /tmp por sesion para no llamar git en cada PreToolUse.
  • Sync stats.total_observations en memory.json desde los JSONL reales.
2
Fase 2 — Importar Dream Cycle de Sinapsis
  • Portar _dream.sh (499 LOC) adaptandolo a la estructura de datos de Cortex (YAML en lugar de JSON index).
  • Implementar deteccion de duplicados con Jaccard similarity sobre triggers+actions de instincts.
  • Implementar deteccion de contradicciones con los 7 pares de palabras opuestas (EN+ES).
  • Implementar staleness scoring con auto-archive no destructivo (mover a archive/, no borrar).
  • Implementar validacion de regex para detectar triggers rotos antes de que fallen silenciosamente.
  • Crear comando /cx-dream con reporte markdown de salud del indice.
3
Fase 3 — Importar mejoras de aprendizaje
  • Occurrence tracking + auto-promote: como hace Sinapsis, promover draft → confirmed automaticamente al llegar a 5+ ocurrencias.
  • Domain pre-filter: antes de evaluar regex, filtrar instincts por dominio del proyecto actual (ahorra evaluaciones innecesarias).
  • Detector de workflow chains: importar el tercer detector de patrones de Sinapsis (secuencias de herramientas que el usuario repite).
4
Fase 4 — Tests (inspirado en Sinapsis)
  • Crear test suite para hooks: observer, injector, session-learner, session-start.
  • Usar el patron de Sinapsis: sandboxes con mktemp -d, fixtures JSON/YAML, asserts en bash.
  • Portar los tests relevantes del Dream Cycle adaptados a la estructura de Cortex.
  • Meta: cobertura minima de cada hook para no romper el pipeline sin enterarse.
5
Fase 5 — Mejoras de infraestructura
  • Extraer JS inline a archivos separados: en lugar de node -e '...' de 200+ lineas dentro de bash, crear archivos .js que el bash invoque. Mejora debugging, linting, testing.
  • Installer automatico: crear un install.sh que configure hooks, cree directorios, y haga backup si ya existe una instalacion previa.
  • CI basico: GitHub Actions que ejecute los tests en cada push (cuando existan).
Resultado esperado

Cortex v3.0 — Lo mejor de ambos mundos

Un sistema con el cerebro entrenado de Cortex (73 instincts, 11 proyectos, datos reales) + las herramientas de mantenimiento de Sinapsis (Dream Cycle, tests, installer, occurrence tracking).
