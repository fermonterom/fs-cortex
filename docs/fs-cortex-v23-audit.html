Arquitectura

Cortex se compone de 4 hooks que se ejecutan en diferentes momentos del ciclo de vida de Claude Code. Combinan Bash, Python inline (heredoc) y Node.js inline.

1 session-start.sh sync 5s SessionStart — Laws + EOD Resume + context.md bridge + reminders. 4-6 Python spawns.
2 observe.sh async 10s Pre+PostToolUse — Captura con secret scrubbing. 5-7 Python spawns × 2 = 10-14 por tool use.
3 injector.sh sync 3s PreToolUse — Reflexes + instincts matching. 1 Node.js process. CONFIRMA inyeccion real-time.
4 session-learner.js sync 15s Stop — Error-fix detection, repetitions, YAML updates, context.md generation.

Pipeline de Aprendizaje

Observe (async, 0 tok) → Learn (Stop hook) → Inject (PreToolUse) → Distill (/cx-distill) → Laws (SessionStart)
Metrica clave: 4 hooks, 1,342 LOC, ~14 process spawns por tool use (10-14 async + 1 sync blocking). El observe.sh con sus 5-7 Python spawns por invocacion es el principal candidato a optimizacion.

Lo Que Funciona Bien (10)

1. Observation Pipeline a 0 Tokens

La decision de diseno mas importante del proyecto

  • observe.sh es async — no bloquea a Claude, no gasta tokens
  • No carga skills ni archivos al contexto durante la observacion
  • Captura tool name, input, output, CWD, timestamp sin coste
  • Todo el analisis ocurre offline (Stop hook) o bajo demanda (/cx-analyze)

2. Confianza Continua 0.0–1.0

5 etapas semanticas con decay temporal

EtapaConfianzaComportamiento
Observacion0.0–0.3Raw, no se inyecta
Hipotesis0.3–0.5Vista 2+ veces, aplica si relevante
Patron0.5–0.73+ ocurrencias, alta probabilidad
Instinct0.7–0.9Validado, auto-aplicado
Law0.9–1.0Multi-proyecto, siempre aplicado

Decay temporal: -0.05 cada 30 dias sin activacion. Auto-archivo por debajo de 0.30.

3. Law Distillation

Instincts maduros se cristalizan en one-liners inyectados siempre

  • Instincts con confianza ≥ 0.90 se destilan a Laws
  • Laws son reglas de una linea (≤120 chars) inyectadas en SessionStart
  • Max 10 Laws activas — ~300 tokens de overhead total
  • Ciclo de vida completo: observacion → hipotesis → patron → instinct → law

4. Promocion Semantica con Jaccard

Decision basada en datos para promover instincts a global

  • Jaccard similarity ≥ 0.70 entre instincts de diferentes proyectos
  • Requiere presencia en 2+ proyectos
  • Confianza promedio ≥ 0.80
  • Promocion automatica a scope global — sin intervencion manual

5. Secret Scrubbing con 5 Patrones

Defensa en profundidad contra leaks en observaciones

  • SECRET_RE — API keys, tokens, passwords, credentials
  • JWT_RE — JWT tokens (patron eyJ...)
  • PEM_RE — Certificados PEM (-----BEGIN...-----)
  • SSH_RE — SSH keys (ssh-rsa, ssh-ed25519...)
  • AWS_RE — AWS Access Keys (patron AKIA...)

6. Escrituras Atomicas

tmp + rename para evitar corrupcion

  • session-learner.js usa fs.writeFileSync(tmp) + fs.renameSync(tmp, target)
  • Registry update con el mismo patron
  • Si el proceso se interrumpe, el archivo original queda intacto

7. Sub-agentes Especializados

3 agentes con modelos optimizados para su tarea

  • cortex-observer (Opus 1M): Analiza observaciones, clustering 4D, propone instincts con evidencia
  • cortex-planner (Sonnet): Descompone tareas complejas en pasos
  • cortex-reviewer (Sonnet ×3 paralelo): Code review con 3 perspectivas simultaneas

8. Backup/Restore Portables

Migracion de conocimiento entre maquinas

  • /cx-backup genera .tar.gz con todo: instincts, laws, reflexes, memory.json, observaciones
  • /cx-restore importa y hace merge inteligente (no sobreescribe, fusiona)
  • Portabilidad total entre maquinas y entornos

9. EOD Auto-inyectado

Quick Resume con guard de lectura unica

  • Se inyecta automaticamente al inicio de cada sesion via hook SessionStart
  • "Ayer trabajaste en X, Y, Z. Prioridades: A, B, C."
  • Guard para evitar inyeccion duplicada si session-start se ejecuta multiples veces

10. Installer Robusto

Preserva datos, backup de configuracion, onboarding

  • Preserva datos de usuario existentes durante upgrades
  • Backup automatico de settings.json antes de modificar
  • Proceso de onboarding integrado

Criticos

Critico

#1 — Prompt injection via instinct action field

injector.sh:196

El campo action de cada instinct se inyecta directamente al contexto de Claude sin sanitizar. Un instinct malicioso (via backup importado o edicion manual) puede contener instrucciones adversariales como "ignore previous instructions".

// injector.sh:196 — action se inyecta tal cual
output += instinct.action;  // Sin sanitizacion

// Fix propuesto:
const sanitized = instinct.action
  .replace(/ignore\s+(all\s+)?previous/gi, '')
  .slice(0, 200);  // Truncar a 200 chars
Critico

#2 — Prompt injection via context.md y EOD Resume

session-start.sh:127-165

El contenido de observaciones previas fluye a context.md y al EOD Resume, que se inyectan en SessionStart sin sanitizar. Si una observacion contiene instrucciones adversariales (capturadas del output de una herramienta), se propagan al contexto de la siguiente sesion.

Critico

#3 — Command injection via cwd en execSync

injector.sh:88-89

JSON.stringify NO escapa $(command substitution) ni backticks dentro de comillas dobles en shell. Un directorio con nombre malicioso podria ejecutar comandos arbitrarios.

// Vulnerable (actual):
execSync("git -C " + JSON.stringify(cwd) + " rev-parse --show-toplevel")

// Fix: execFileSync bypasea shell
execFileSync("git", ["-C", cwd, "rev-parse", "--show-toplevel"])

Altos

Alto

#4 — Race condition archive-then-write en observe.sh

observe.sh:253-261

TOCTOU (Time-Of-Check-Time-Of-Use) entre comprobar el tamano del archivo y ejecutar mv. Si dos instancias de observe.sh corren simultaneamente, ambas detectan el archivo grande y ambas intentan archivarlo. Una falla silenciosamente y las observaciones se pierden.

Alto

#5 — No flock en macOS — interleaving JSONL

observe.sh:320-329

Append a observations.jsonl sin lock. macOS no tiene flock nativo. Si dos sesiones escriben simultaneamente, las lineas JSON pueden intercalarse produciendo JSONL corrupto que rompe el analisis posterior.

Alto

#6 — Secret scrubbing incompleto

observe.sh (Python heredoc)

Tiene 5 patrones (API keys, JWT, PEM, SSH, AWS) pero NO detecta:

  • GitHub tokens: ghp_*, ghs_*, github_pat_*
  • Stripe keys: sk_live_*, pk_live_*
  • Connection strings con credenciales embebidas: postgresql://user:pass@host
  • Supabase keys: sb_*, sbp_*
Alto

#7 — Path injection en Python heredoc

session-start.sh:92-101

$HOME se interpola en un heredoc Python con comilla simple. Si $HOME contiene una comilla simple (raro pero posible), el script Python se rompe o ejecuta codigo inesperado.

# Vulnerable:
python3 -c "
home = '$HOME'  # Si HOME contiene ', rompe el script
"

# Fix: usar os.environ
python3 -c "
import os
home = os.environ['HOME']
"
Alto

#8 — Non-atomic settings.json write en install.sh

install.sh:293-297

La escritura de settings.json durante la instalacion no usa el patron tmp+rename. Si el proceso se interrumpe durante la escritura, settings.json queda corrupto y Claude Code no arranca.

injector.sh:45

Los triggers de instincts son regex editables por el usuario sin timeout ni validacion de complejidad. Un trigger patologico como (a+)+$ puede bloquear el hook sync durante segundos en CADA tool use.

Cortex proposals pipeline

El archivo de propuestas de instincts crece indefinidamente. Sin rotacion ni archivo, puede alcanzar tamanos que ralentizan la lectura y el analisis.

#11 — session-learner.js lee TODAS las observaciones en memoria

session-learner.js

Al ejecutarse en Stop, lee las observaciones de TODOS los proyectos en memoria. Con multiples proyectos activos y semanas de observaciones acumuladas, el consumo de memoria puede ser significativo.

#12 — Token inflation sin cap en SessionStart

session-start.sh

La inyeccion de Laws + EOD + context.md no tiene limite de caracteres. Si el context.md crece (por acumulacion de notas de sesion), el coste en tokens de SessionStart crece sin control.

Medio

#13 — Commands silently overwritten en upgrade

install.sh:150-155

Los comandos slash custom del usuario se sobreescriben sin aviso durante un upgrade. Si el usuario ha editado un comando para adaptarlo a su workflow, pierde los cambios.

Medio

#14 — Dedup file en /tmp con path predecible

observe.sh:90

El archivo de deduplicacion usa un path predecible en /tmp. Otro usuario del sistema podria crear un symlink malicioso en esa ruta para redirigir observaciones o causar errores.

Medio

#15 — obs-count race condition read-modify-write

observe.sh:342-354

El contador de observaciones se lee, incrementa y escribe sin lock. Dos instancias concurrentes pueden leer el mismo valor, incrementar ambas, y sobreescribir una a la otra — perdiendo un incremento.

Vulnerabilidades de Seguridad

Critico

5A — Prompt Injection (2 vectores)

Vector 1: instinct action fields se inyectan sin sanitizar (injector.sh:196). Un backup malicioso importado via /cx-restore puede inyectar instrucciones adversariales en cada tool use.

Vector 2: context.md y EOD Resume (session-start.sh:127-165) contienen contenido derivado de observaciones. Si una herramienta devuelve output con instrucciones adversariales, estas se propagan al contexto de la siguiente sesion.

Fix: Sanitizar action (strip "ignore previous", truncar a 200 chars). Sanitizar contenido de context.md antes de inyectar.

Alto

5B — Command Injection

injector.sh:88-89

execSync con JSON.stringify no previene $(command substitution) en shell. Un directorio con nombre malicioso podria ejecutar comandos arbitrarios. Fix: execFileSync("git", ["-C", cwd, ...]) que no pasa por shell.

Alto

5C — Secret Scrubbing Incompleto

5 patrones cubren API keys, JWT, PEM, SSH, AWS. Pero faltan:

  • GitHub tokens: ghp_*, ghs_*, github_pat_*
  • Stripe keys: sk_live_*, pk_live_*
  • Connection strings: postgresql://user:pass@host, mongodb+srv://
  • Supabase keys: sb_*, sbp_*
Medio

5D — ReDoS en Instinct Triggers

injector.sh:45

Los triggers son regex editables sin timeout por regex ni validacion de complejidad. Un trigger patologico bloquea el hook sync (3s timeout) en cada tool use.

Fix: vm.runInNewContext con timeout o limite de alternaciones/cuantificadores anidados.

Medio

5E — Path Injection en Python Heredoc

session-start.sh:92-101

$HOME interpolado en Python heredoc. Una comilla simple en $HOME rompe el script. Fix: usar os.environ['HOME'].

Medio

5F — File Locking Ausente en macOS

observe.sh:320-329

macOS no tiene flock nativo. Appends concurrentes a observations.jsonl sin lock pueden producir lineas JSON intercaladas y corrupcion del archivo.

Fix: Usar shlock o named pipe para serializar escrituras.

Lo que Cortex NO tiene (y Sinapsis si)

Contexto: Sinapsis (sinapsis-3.2) es un sistema paralelo de aprendizaje para Claude Code. Estas son las funcionalidades que Sinapsis implementa y que Cortex v2.3 no tiene. Cada una representa una oportunidad de mejora.
GAP CRITICO

1. Dream Cycle — 499 LOC de Higiene Determinista

Sinapsis tiene _dream.sh con:

  • Jaccard dedup — detecta instincts duplicados (umbral 0.80)
  • Contradiccion detection — 7 pares de palabras opuestas EN+ES
  • Staleness scoring — fresh/stale/archive_candidate con auto-archivo
  • Regex validation — detecta triggers rotos u overly-broad
  • Health score — 0-100 con penalizaciones ponderadas
  • Lock file exclusivo con deteccion de lock obsoleto (>1h)
  • Atomic writes con tmp+rename

Cortex tiene /cx-audit con overlap detection basico, pero no es determinista, no tiene tests, no tiene Jaccard dedup, no detecta contradicciones, y no calcula health score.

Impacto: Sin Dream Cycle, el indice de instincts acumula duplicados, contradicciones y entradas obsoletas sin forma automatica de limpiarlos.

GAP CRITICO

2. Suite de 40 Tests

Sinapsis tiene 25 tests unitarios + 15 tests E2E para el Dream Cycle:

  • Tests de Jaccard similarity con fixtures conocidos
  • Tests de contradiccion detection con edge cases
  • Tests E2E que ejecutan el ciclo completo contra un directorio sandbox
  • Ejecutables con test-dream.sh usando mktemp sandboxes

Cortex tiene 0 tests. Ningun hook, ningun comando, ningun agente tiene cobertura de tests. Para produccion, esto es inaceptable.

Impacto: Cualquier cambio en los hooks puede romper el pipeline de aprendizaje sin que nadie lo detecte hasta que falle en uso real.

GAP MODERADO

3. Skill Router con Token Budgeting

Sinapsis tiene un launcher con 3 modos (Skills on Demand / Manual / Freestyle), picker interactivo, y catalogo de tokens por skill. Cortex no gestiona skills — diferente scope, pero la idea de token budgeting (cuanto cuesta en contexto cada pieza inyectada) es valiosa y trasladable.

GAP MENOR

4. Onboarding Guiado de 8 Fases

Sinapsis tiene un onboarding progresivo de 8 fases que guia al usuario nuevo paso a paso. Cortex tiene un install.sh basico que configura hooks y sale. La experiencia de primer uso es significativamente peor.

GAP MENOR

5. Soporte Windows

Sinapsis tiene install.bat (aunque desincronizado con la version actual — bug #9 de su auditoria). Cortex solo soporta macOS/Linux. No hay install.bat ni adaptaciones para PowerShell.

GAP MENOR

6. Workflow Chain Detection (Trigramas)

El session-learner de Sinapsis detecta trigramas de tools repetidos (e.g., "Read → Edit → Bash" como patron frecuente). Cortex solo detecta error-fix y repeticiones simples, sin capacidad de detectar workflows multi-paso recurrentes.

GAP MENOR

7. User Correction Detection

Sinapsis detecta cuando el mismo archivo se edita 2+ veces en una ventana de 10 tool uses, interpretandolo como una correccion del usuario (Claude hizo algo mal y el usuario lo corrige). Cortex no tiene esta heuristica.

Python vs Node.js vs Bash — Analisis de Migracion

Pregunta clave: Cortex usa una mezcla de Bash, Python inline (heredoc), y Node.js inline. Hay que consolidar? Migrar todo a un solo lenguaje? La respuesta es matizada.

Estado Actual

HookStackProcesosTiempo
observe.sh Bash wrapper + 5-7 Python heredoc inline 7 procesos ~600ms/call
injector.sh Bash wrapper + 1 Node.js inline 2 procesos ~150ms/call
session-start.sh Bash wrapper + 4-6 Python heredoc inline 5-7 procesos ~400ms/call
session-learner.js Node.js standalone 1 proceso ~300ms/call

Propuesta: Consolidar observe.sh en Python Puro

El cambio con mayor impacto en rendimiento

Flujo actual (7 procesos):

bash → python (cwd)
     → python (agent_id)
     → python (tool_name)
     → python (hash)
     → python (registry)
     → python (parse+scrub+write)
     → git (remote)
= 7 procesos, ~600ms

Flujo propuesto (2 procesos):

bash (read stdin) → python (todo el procesamiento)
= 2 procesos, ~100ms

Ahorro: ~500ms por invocacion × 2 (pre+post) × 200 tool uses = ~200 segundos de CPU por sesion.

Por que Python es la eleccion correcta: json nativo, regex nativo, file I/O simple, hashlib (sha256) nativo. No necesita npm install ni dependencias externas.

Por que NO Migrar injector.sh a Python

  • Diferencia de startup minima: Node.js ~100ms vs Python ~50ms. No justifica el esfuerzo.
  • Node.js regex engine mas rapido que Python re para patrones complejos de matching
  • injector.sh ya es eficiente: 1 proceso, ~150ms, sync blocking. Es el hot path mas importante y ya esta optimizado.
  • El parser YAML custom funciona para el caso de uso actual sin necesidad de dependencias externas.

Por que NO Migrar session-learner.js a Python

  • Ya es un .js standalone (no inline en bash heredoc). Archivo limpio y testeable.
  • Atomic writes con fs.renameSync nativo — funcionalidad equivalente en Python pero sin ganancia.
  • 573 LOC bien estructurado — migrarlo es esfuerzo sin beneficio.
  • Se ejecuta 1 sola vez por sesion (Stop hook) — no hay ganancia de performance.

Veredicto: Migracion Selectiva

Migrar SOLO observe.sh y session-start.sh a Python puro. Mantener injector.sh (Node) y session-learner.js (Node).
