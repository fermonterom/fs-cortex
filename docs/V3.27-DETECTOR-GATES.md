## Background

v3.27.0 added 3 new detectors to `hooks/session-learner.js`:

| Detector | Emits | Confidence | Auto-validate |
|---|---|---|---|
| `detectAgentSubtypes` | proposals on Agent subtype error rate | 0.45 | ❌ < 0.50 → pending manual `/cx-validate` |
| `detectFileCoupling` | proposals on edit pair frequency | 0.40 | ❌ < 0.50 → pending manual `/cx-validate` |
| `detectTimeOfDayPatterns` | side-effect only (writes `productivity-patterns.json`) | n/a | n/a |

Plus v3.26.0's `applyCrossDayBoost()` wraps all 5 proposal-emitting detectors (the 3 new + 2 pre-existing).

The thresholds (3 uses / >30% errors / 5 sessions / etc.) were chosen by Opus 4.7 design and never measured against real production traffic. **Goal:** validate that the thresholds produce useful signal, not noise.

## Gate A — `detectAgentSubtypes` produces signal, not noise

**Pass criterion:** between **2026-05-09 and 2026-05-11**, at least 1 proposal with `source: session-learner:agent-error-rate` is emitted, AND the manual accept/reject ratio (when reviewed via `/cx-validate`) is ≥ 50% accept (i.e. half or more of emissions are useful).

**Why this threshold:** if 0 proposals → threshold too high (3 uses + 30% errors is rare). If accept ratio < 50% → threshold too low (noise dominates).

**How to measure on Monday:**

```bash
python3 -c "
import json
ps = json.load(open('/Users/fmm/.claude/cortex/proposals.json'))
agent_subtype = [p for p in ps if p.get('source') == 'session-learner:agent-error-rate']
total = len(agent_subtype)
accepted = sum(1 for p in agent_subtype if p.get('status') == 'accepted')
rejected = sum(1 for p in agent_subtype if p.get('status') == 'rejected')
pending  = sum(1 for p in agent_subtype if p.get('status', 'pending') == 'pending')
ratio = accepted / max(total, 1) * 100
print(f'detectAgentSubtypes: total={total} accepted={accepted} rejected={rejected} pending={pending} accept_pct={ratio:.0f}%')
print('PASS' if total >= 1 and ratio >= 50 else 'PENDING' if total == 0 else 'FAIL')
"
```

**Action on Monday:**

- **PASS** → keep as-is. Document the measured threshold values in CHANGELOG.
- **FAIL (low accept ratio)** → raise either `AGENT_SUBTYPE_MIN_USES` (currently 3) or `AGENT_SUBTYPE_ERROR_THRESHOLD` (currently 0.30). New release v3.27.x.
- **PENDING (zero emits)** → leave threshold; needs more data. Re-check 2026-05-13.

## Gate C — `detectTimeOfDayPatterns` accumulates useful aggregates

**Pass criterion:** by **2026-05-11**, `~/.claude/cortex/productivity-patterns.json` exists, has data in **≥2 of 4 buckets** (morning/afternoon/evening/night), has **≥4 distinct hours** with `total > 0`, and the `insights` array is non-empty.

**Why this threshold:** the detector runs on every Stop hook, so even minimal activity produces data. If after 2 days only 1 bucket has data, the bucketing is wrong or operator activity is too narrow. If insights array is empty after 2 days, the threshold (`error_rate > 0.10`) is wrong.

**How to measure on Monday:**

```bash
python3 -c "
import json, os
path = '/Users/fmm/.claude/cortex/productivity-patterns.json'
if not os.path.exists(path):
    print('FAIL: productivity-patterns.json does not exist')
    exit(1)
d = json.load(open(path))
buckets = d.get('buckets', {})
filled_buckets = sum(1 for b in buckets.values() if b.get('total', 0) > 0)
hours_with_data = sum(1 for h in d.get('by_hour', {}).values() if h.get('total', 0) > 0)
insights = d.get('insights', [])
print(f'buckets_filled={filled_buckets}/4  hours_with_data={hours_with_data}  insights={len(insights)}')
ok = filled_buckets >= 2 and hours_with_data >= 4 and len(insights) >= 1
print('PASS' if ok else 'FAIL')
print('Insights:')
for i in insights:
    print(f'  - {i}')
"
```

**Action on Monday:**

- **PASS** → keep `> 0.10` insight threshold and 4-bucket layout. Document.
- **FAIL (no insights)** → raise/lower the `error_rate > 0.10` cutoff in `detectTimeOfDayPatterns()` based on observed bucket error rates.
- **FAIL (only 1 bucket)** → not a code bug, just narrow operator window. Wait more days.

## Gate D — `applyCrossDayBoost` actually boosts something

**Pass criterion:** by **2026-05-11**, `~/.claude/cortex/cross-day-tracker.jsonl` has **≥10 entries** AND at least 1 proposal in `proposals.json` has `cross_day_count >= 2` (i.e. the same pattern was detected on 2+ distinct days, triggering a `+0.05` boost).

**How to measure on Monday:**

```bash
python3 -c "
import json, os
tracker = '/Users/fmm/.claude/cortex/cross-day-tracker.jsonl'
proposals = '/Users/fmm/.claude/cortex/proposals.json'

if not os.path.exists(tracker):
    print('FAIL: cross-day-tracker.jsonl missing')
    exit(1)
entries = sum(1 for _ in open(tracker))
boosted = 0
if os.path.exists(proposals):
    ps = json.load(open(proposals))
    boosted = sum(1 for p in ps if p.get('cross_day_count', 0) >= 2)
print(f'tracker_entries={entries}  boosted_proposals={boosted}')
print('PASS' if entries >= 10 and boosted >= 1 else 'PENDING' if entries < 10 else 'FAIL')
"
```

**Action on Monday:**

- **PASS** → cross-day tracking working. Document.
- **FAIL (entries but no boost)** → Jaccard 0.70 threshold may be too strict for real-world trigger variation. Lower to 0.60 or check `pattern_id` exact-match logic.
- **PENDING (low entries)** → operator was less active than expected. Wait more days.

## Gate E — Threshold confidence values are sane (sanity-only)

**Pass criterion:** confirm via `/cx-validate` review that the human (Fer) actually accepts proposals with confidence 0.40-0.45 at a similar rate to existing 0.50+ proposals. If the new detectors' lower confidence makes them disproportionately rejected, the design is off.

**How to measure on Monday:**

```bash
python3 -c "
import json
ps = json.load(open('/Users/fmm/.claude/cortex/proposals.json'))
def stats(name, src_prefix):
    items = [p for p in ps if p.get('source','').startswith(src_prefix)]
    total = len(items)
    accepted = sum(1 for p in items if p.get('status') == 'accepted')
    pct = accepted / max(total,1) * 100
    return f'{name:30s} n={total:4d}  accept_pct={pct:5.1f}%'

print(stats('error-fix (0.50)',           'session-learner:error-fix'))
print(stats('correction (0.45)',          'session-learner:correction'))
print(stats('workflow (0.50)',            'session-learner:workflow'))
print(stats('agent-pattern (0.50)',       'session-learner:agent-pattern'))
print(stats('agent-error-rate (0.45)',    'session-learner:agent-error-rate'))
print(stats('file-coupling (0.40)',       'session-learner:file-coupling'))
print()
print('Compare new (0.40, 0.45) vs old (0.45, 0.50). New must not be < 50% of old.')
"
```

**Action:** if new detectors have <50% of the accept ratio of old detectors at similar confidence, raise their confidence (e.g. agent-subtype 0.45 → 0.50, file-coupling 0.40 → 0.45). New release.
